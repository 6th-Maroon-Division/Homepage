Authenticate the website transport with its bearer API key. Handle canonical error envelopes, correlation IDs, cancellation, timeouts, and retryable errors. 2. **Configuration and diagnostics.** Fetch /discord/config, validate schema compatibility, apply a complete snapshot, and heartbeat only the revision actually applied. Report supported schema versions, bounded issue codes, capability results, queue counts, and inventory observation time. Verify configured roles/channels and actual Discord permissions/hierarchy. Use verified cached configuration only within its website-configured freshness window; pause new automated moderation, role and nickname mutations after expiry. Alert the locally configured Discord user once per outage and on recovery without flooding them.
3. **Durable execution.** Persist separate event resume cursors for rank, orbat, training, discord and member. Use meta.resumeCursor, including on the last page; SSE Last-Event-ID must agree with any cursor. Events invalidate data: refetch current authoritative state. Claim website commands, persist claim identity and generation, renew leases during long retries, and reconcile uncertain Discord side effects before retrying. Never treat a lost HTTP response as proof of failure. Keep local state across restarts.
4. **Join roles, welcomes and reaction menus.** Apply configured defaults only on joins unless an explicit bulk operation was reviewed. Three join attempts use configured delays; preserve successful partial assignments. Welcome on every join by default, even while join-role assignment is failing. Publish/edit menu messages through explicit commands, acknowledge actual channel/message IDs, and reload published references after restart. Add a role on reaction; remove it when that reaction is removed regardless of original grant source. Enforce optional single-choice within that category only. Deleted menu entries preserve existing roles. Report bounded automatic-operation outcomes and stop/cancel join assignment when the honeypot chooses a ban.
5. **Announcements and ORBAT interactions.** Execute explicit publish/refresh/re-ping commands using saved per-ORBAT destination and text. Never announce merely because an ORBAT exists. Enumerate stored announcements for reconciliation; fetch the render snapshot and live website roster image immediately before editing. Serialize edits per message, obey content revisions and batching, send empty allowed mentions for automatic updates, and acknowledge the actual revision/target. On stale receipt, refetch and repair even if an earlier receipt matched. Mark missing messages; recreate only through the explicit no-ping repost command. Build signup/change/cancel and availability controls using the linked-member adapters and stable Discord-interaction idempotency keys. Show disabled controls/reasons when unavailable; recheck eligibility on every mutation. Do not expose private absence notes in public embeds or images.
6. **Ranks and names.** Use website rank mappings and linked-member data. Rank is authoritative on the website. Synchronize accepted base names in both directions, with the prefix only in the Discord server nickname. Include moderator edits when observable. Use nameRevision optimistic concurrency and stop feedback loops. Website names win at first linking; clearing a nickname restores the accepted formatted website name. Do not save a bot-truncated Discord nickname as a new base name or silently promote a website user from a Discord role change.
7. **Moderation and evidence.** Capture a honeypot trigger and current roles, then use website classification: exemptions first; configured membership roles timeout for at least 24 hours; otherwise ban, including failed default-role assignment. Report inaccessible or oversized captures as failures. Respect all evidence size limits. Keep temporary evidence secure and remove acknowledged copies according to the agreed lifecycle; the website owns lasting retention and seven-day recovery. Expired/stale/partially failed previews need a new reviewed action. 9. **Notification preferences.** Consume the existing website preferences as two dimensions: delivery method (Discord DMs/channel mentions) and message type (ORBAT, training scheduled/updated/cancelled/reminders, promotions). 10. **Verification and operations.** Complete ACCEPTANCE_CHECKLIST.md. ## Fixed behavior

Use the full specification for details. Do not reopen confirmed defaults: configurable membership-role IDs, welcome on join including returning members, three join-role attempts, reaction removal removes its mapped role, deleted entries retain roles, >=24-hour timeouts with early release, 30-minute cleanup, >=7-day configurable/indefinite evidence retention, seven-day recovery after any deletion, and manual deletion even for indefinite evidence. Permission/validation failures need correction rather than blind retries. Rate-limit handling belongs in the Discord adapter and must not shorten Discord's requested wait.
