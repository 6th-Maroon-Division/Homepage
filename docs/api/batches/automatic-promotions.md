# Automatic promotions

`GET /api/ranks/promotions/automatic` replaces `/api/bot/promotions/auto`. Required `rank:manage_promotions`, session or active bot (superadmin). Live hierarchy visibility is applied in SQL before pagination. Query only days1..3650(default7), limitpositive capped100(default50), cursorpositiveInt32; duplicate/unknown/invalid400. Descending history IDs, actual lookahead, string nextCursor or null. Looks back days*24hours in UTC and retains historical triggeredBy containing auto behavior.

DTO array: `{id,userId,previousRankName:string|null,newRankName,createdAt:ISO-UTC,triggeredBy,outcome,user:{id,username:string|null,discordId:string|null}}`. No account lists, Steam/email/avatar, rank history note/declineReason, or current-rank substitute. Audits `user_data.read` resource `rank_history` for returned other user IDs only (bots all); no snapshots. Empty/self-only no read audit; required audit failure500 withholds records.

`POST /api/ranks/promotions/automatic` replaces `/api/ranks/auto-rankup`. Strict empty JSON object and no queries. Same auth/permission; candidate selection limits to visible users with a rank, completed interview, and not retired. Each candidate gets independent Serializable eligibility/hierarchy checks and atomic promotion, history, inbox+recipient, outbox and audit. Preserves rank-state flags and computes current main-operation/legacy attendance. Automatic eligible lanes only; current pending proposals are closed with a second audit. Stale pending proposals fail that user's processing. Identical automatic source/actor conventions to immediate proposal promotion; history auto, audit actual user/token, outbox user.rank_changed source automatic.

Response200 `{data:{promotedCount,errorsCount,ineligibleCount},meta:{}}`. Counts indicate committed promotions, per-user transaction failures, and attendance-short automatic lanes respectively; other skipped lanes are omitted. The run is deliberately per-user atomic, preserving earlier committed successes if a later target fails. No personal error/success arrays are returned. A storage/audit failure rolls back that target and increments errorsCount. No sensitive exception strings in logs/responses. Postcommit notification failures do not count committed mutations as failures. Global/query/JSON/auth/database selection failure uses standard errors.

PendingPromotionsClient now calls the canonical POST via apiRequest with `{}`, reads counts, and drops logging of old personal detail arrays. No schema changes.
