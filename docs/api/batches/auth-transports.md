# Browser authentication transports

Three route files intentionally remain browser-protocol exceptions:

- `/api/auth/[...nextauth]` GET/POST: NextAuth's Discord OAuth, session, CSRF, signin and signout protocol. NextAuth retains its redirects, cookies, provider state/CSRF checks and native response bodies.
- `/api/auth/steam-login` GET: begins a browser-bound Steam OpenID login/link flow and redirects to Steam.
- `/api/auth/steam-callback` GET: verifies the OpenID response, links/signs in the account, then redirects to the profile or ORBAT page.

These routes cannot require a preexisting session or bot token: they establish the browser session. They do not issue bot credentials or provide an alternate bot authentication path. The common JSON envelope is deliberately not applied to provider redirects, callback parameters, session cookies, or NextAuth's protocol-defined JSON. Business APIs continue to validate live sessions/grants and database bot tokens using the common handler.

## Security fixes

The old Steam callback trusted an unverified `openid.claimed_id`, and `/api/auth/steam-signin?userId=...` could issue any Steam-linked user's session without identity proof. The standalone signin endpoint and unused unsafe `lib/steam-provider.ts` are removed. Sessions are now issued only inside the verified callback.

Login creates a random 256-bit browser state, stores only its SHA-256 hash with the initiating user ID and a ten-minute expiry, and sets an HttpOnly, SameSite=Lax cookie. HTTPS deployments use the Secure `__Host-steam-state` cookie. The return URL includes the state. Callback requires matching URL/cookie state, a live unexpired database attempt, and the same initiating session identity; linking cannot change identity halfway through the flow.

Callback validates duplicate/unknown fields, protocol namespace/mode, trusted Steam identifier host/path, identical claimed and asserted identity, exact state-bearing return URL, required signed fields, and a fresh UTC response nonce. It verifies the assertion via `check_authentication` against the pinned HTTPS Steam endpoint, with redirects disabled and bounded network timeouts. Steam profile identity must equal the verified Steam ID. Valve documents both the historical HTTP identifier and HTTPS transport; HTTP/HTTPS identifier URIs are accepted, but verification and API network calls always use pinned HTTPS endpoints. No callback URL can choose an upstream host.

The attempt is consumed in the same Serializable transaction as account creation/linking and its audit. Replay, concurrent consumption, or audit failure cannot mint a session. Linking refuses a Steam identity owned by another user. Pending attendance processing occurs after commit and cannot invalidate a successful verified login. Its own Serializable transaction links only pending unowned/already-owned events and writes `attendance_events.linked` with event IDs and the validated login actor; audit failure rolls back all links. Standalone calls use an explicit system audit actor. Removed unused legacy bulk pending-event helpers. Redirects clear the state cookie and use no-store/no-referrer headers. Missing authentication secrets or invalid configured origins fail closed. Production requires HTTPS `NEXTAUTH_URL`.

Discord signin now validates the provider identity, checks the live initiating user, refuses linking an account belonging to somebody else, and commits account/profile changes with a minimal authentication audit. Cookie chunking is supported when detecting an existing session. JWT creation resolves only the verified Discord namespace; it no longer prefers a Steam account sharing the same string ID. Subsequent refresh uses the already-signed internal user ID, preventing cross-provider reassignment. Deleted users lose cached identity/grants on explicit refresh; business APIs additionally check live existence on every call.

Auth audits are `auth.steam.signed_in`, `auth.steam.linked`, `auth.discord.signed_in`, or `auth.discord.linked`, resource `auth_account`, with the authenticated internal actor and target ID. They contain no raw assertions, nonce/state, provider IDs, cookies, access tokens, names, or profile snapshots. Custom callback denials also write metadata-only `access.denied` events with an anonymous actor; failed denial-audit storage still denies the request. Browser errors retain protocol redirects.

## Database and tests

`SteamLoginAttempt` has `stateHash` primary key, nullable scalar initiating `userId`, UTC timestamptz `expiresAt`/`createdAt`, and an expiry index. The scalar user ID intentionally does not cascade away; callbacks independently require a still-existing user and reject stale attempts. Expired attempts are deleted when a new login begins. Migration `20260919020000_steam_login_attempt` was generated by Prisma schema comparison without touching a deployed database.

Unit files: `tests/api/steam-auth.test.ts` (22 cases), `tests/api/nextauth-transport.test.ts` (10 cases). Real Prisma files: `tests/api-integration/steam-auth.test.ts` (4 cases), `tests/api-integration/nextauth-transport.test.ts` (3 cases). Coverage includes takeover attempts, state replay and expiry validation, mismatched browser/session/provider identity, provider-ID collision, account-link ownership, real encrypted session claims, and audit rollback. Two additional real Prisma cases in `tests/api-integration/auth-pending-events.test.ts` prove account-link event audit attribution and rollback. Provider network responses are mocked; live provider acceptance still requires a configured deployment smoke test.

Protocol references: [OpenID 2.0 assertion verification](https://openid.net/specs/openid-authentication-2_0.html#verification), [Steamworks browser authentication](https://partner.steamgames.com/doc/features/auth#website).
