# Website realtime streams

Eight GET streams use one bounded SSE transport: public `/orbats/events` and `/orbats/{id}/events`; protected `/users/{id}/events`, `/users/events`, `/users/{id}/messages/events`, `/catalog/events`, `/ranks/promotions/events`, `/training-requests/{id}/events`. Remove session-only `/user/events`, `/admin/users/events`, `/admin/catalog/events` and `/messaging/events`. Website callers use canonical URLs and decode `{data,meta}` frames.

Anonymous ORBAT viewing remains supported; supplied invalid/revoked bot credentials fail. Public events discard staff-only changes and never pass actor IDs or arbitrary payloads. Calendar creation events retain only operation display fields; other notifications carry operation ID/type/time. No personal data is delivered by these public streams.

Protected handshakes validate live session/bot identity, strict IDs and no query keys. Profile access is self or existing staff permission plus target hierarchy; broadcast profile streams filter each target before delivery. Inbox is owner/superadmin; request chat is owner/training staff; promotion queue needs rank:manage_promotions; catalog events require permission for that event's resource family. Session-only me aliases are supported for profile/inbox. Notifications contain minimal metadata, not arbitrary internal payloads, message text or staff identities.

Each event and 15-second heartbeat revalidates credentials and access; revoked/expired principals close the stream with a denied audit. Returned other-user profile/inbox/request target IDs are audited before delivery; audit failure closes without exposing the event. Connection frames contain no target personal data. Metadata-only catalog/promotion events do not create personal read audits.

SSE transport retains protocol content type, retry3000, IDs, UTC timestamp heartbeats and `{data,meta}` data frames. It cleans up listeners/timers for abort, reader cancellation, already-aborted requests and failures, caps queued callbacks and output buffers, and serializes asynchronous validation/auditing to prevent overlapping deliveries. These are transient invalidation notifications, not durable replay: clients fetch canonical resources on reconnect. Durable cursor feeds are separately documented at `/events`.

Validation: unit tests exercise every stream route, anonymous/token/session access, hierarchy filtering, payload minimization, before-delivery audits, credential revocation, abort/cancel, heartbeats and bounded queues. Three isolated Prisma integrations prove actual permission/token revocation and public privacy against the database.
