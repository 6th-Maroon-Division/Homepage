# ORBAT and permission templates

All listed methods accept a live website session or active database bot token. Bots retain superadmin rights. Responses use `{data,meta}` and shared `{error:{code,message,details,correlationId}}`; malformed JSON, IDs or query parameters return 400, invalid fields 422, absent records/references 404, insufficient rights 403 and database conflicts 409.

| Endpoint | Methods | Authorization and behavior |
| --- | --- | --- |
| `/api/templates` | GET, POST | GET requires any template create/edit/delete or ORBAT create/edit permission. Lists active templates. POST requires `template:create`. |
| `/api/templates/{id}` | GET, PATCH, DELETE | GET uses the same read access, including archived templates. PATCH requires `template:edit`; DELETE requires `template:delete` and archives with `isActive:false`, returning `data:null`. |
| `/api/templates/access` | GET | Any valid user/bot; returns `canRead`, `canCreate`, `canEdit`, `canDelete` from current grants. |
| `/api/permissions/templates` | GET, POST | Requires `user:manage_permissions`. POST creates a new permission template; duplicate names return 409. |
| `/api/permissions/templates/{id}` | PATCH, DELETE | Requires `user:manage_permissions`. DELETE removes the template and its items, returning `data:null`. |

Both collection GETs accept only `limit` (default 50, maximum 100) and positive numeric `cursor`. IDs are ascending with actual lookahead and `meta:{limit,nextCursor}`; terminal `nextCursor` is null. Repeated/unknown parameters are rejected. Other methods accept no query parameters. All path and body IDs are positive Int32 numbers (path IDs are decimal strings).

ORBAT template POST requires trimmed `name` and nonempty `slotsJson` squads, each `{name,orderIndex,slots}` with nonempty slots `{name,orderIndex,maxSignups,squadRoleId?}`. Positions are unique nonnegative integers within their respective collections. Role IDs are nullable and max signups are positive. Optional `frequencyIds` are unique numeric IDs; optional `tempFrequencies` items require `frequency,type,isAdditional,channel,callsign`. Radio/role references are validated; retired roles return 409. Read DTOs resolve current role names and prerequisite ID arrays, normalize legacy stored JSON, and exclude source signup IDs, copied user records, client `_id` values and singular prerequisite aliases.

Optional nullable trimmed fields are `description,category,tagsJson,timezone,bluforCountry,bluforRelationship,opforCountry,opforRelationship,indepCountry,indepRelationship,iedThreat,civilianRelationship,rulesOfEngagement,airspace,inGameTimezone,operationDay,startTime,endTime`; `isSideOp` is optional boolean. PATCH accepts a nonempty subset plus boolean `isActive`, preserving omitted fields. `startTime` and `endTime` are nullable HH:MM preset clock settings, not instants. Actual metadata timestamps are UTC ISO strings ending in Z. Creation metadata and usage count are read-only.

ORBAT template DTOs retain nullable minimal `createdBy:{id,username,avatarUrl}` and nullable `createdById`. Bot creation sets both to null. Deploy the Prisma-generated `20260918130000_nullable_template_creator` migration before serving bot template creation; it preserves the existing Restrict relation. Migration generation used schema comparison, not a development database.

Permission template POST requires trimmed `name` and `permissions:[{permissionId,value}]`; description is optional nullable trimmed text. PATCH accepts a nonempty subset, replacing the complete permission set only when supplied. Permission IDs must be unique existing numeric IDs, values nonnegative Int32 integers no greater than each permission’s configured `maxValue` (normally 255), and at least one value positive. Above-catalog values return 422 before writes. Zero values are validated then excluded from storage. The common DTO is `{id,name,description,createdAt,updatedAt,permissions:[{permissionId,key,value}]}`, with UTC timestamps and entries sorted by permission ID. Removed PUT methods become PATCH; POST `overwrite` and old `{success,template}`/`{templates}` response wrappers are removed. The website edits an existing template explicitly instead of silently overwriting through POST.

Mutations and audits share Serializable Prisma transactions. ORBAT template audits use IDs/flags/counts, excluding briefing text; permission-template audit snapshots contain permission IDs/values, excluding descriptions. Other-user creator reads audit only returned page creators, excluding self and lookahead; bots log all returned creators. General permission-template and access reads are not audited. Post-commit template catalog notification failure does not roll back a successful mutation.

The template editor sends only writable fields, strips client IDs and derived role requirements, and uses PATCH. Template list callers collect all pages and sort for display. Permission-template UI refreshes select from the newly returned rows, fixing stale selection after creation/deletion.

Tests: `tests/api/templates.test.ts` exercises all ten methods with user/bot authentication, live rights, strict validation, references, pagination, UTC serialization, audit scope/failure and database errors. `tests/api-integration/templates.test.ts` exercises both real Prisma lifecycles, cascades/soft deletion, null bot creators, constraint conflicts, pagination, permissions, and transactional rollback on audit failure against isolated Prisma-managed PGlite. Root CI runs the combined unit coverage and integration gates; other API families remain separate migration work.
