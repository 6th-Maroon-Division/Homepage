# Rank migration

Canonical `POST /api/ranks/migrate/preview` and `POST /api/ranks/migrate/apply` retain computational POST requests to share a strict JSON strategy payload. No query parameters. Payload is `{strategy:'recalculate'|'grandfather'}` or `{strategy:'map',rankMappings:[{oldRankId,newRankId}]}`. Map entries must be nonempty, exact numeric positive Int32 references with unique oldRankId; mappings are forbidden for other strategies. Missing references404 before any writes; bad JSON/query400, payload422, authentication401, permission403, concurrency409.

Both accept live session or active Bearer bot and require global `rank:edit`, including self. SQL scopes users to self or strictly lower rank:edit hierarchy; superadmin bots see all. Every selected user permission is rechecked within the Serializable transaction before writes. All selected users with a current rank are included; users without rank are excluded consistently from totals. Preview and apply read the same plan; apply recomputes it against current state rather than trusting a previous preview.

Semantic correction: attendanceSinceLastRank stores an accumulated attendance baseline, not attendance available for recalculation. Recalculate now uses actual counted main-operation present statuses plus legacy attendance to choose the highest rank whose individual attendance threshold is satisfied (null/zero means no threshold). This preserves the existing highest-threshold migration strategy, distinct from normal promotion eligibility/training checks. On changed rank, reset the baseline to actual attendance rather than zero; history stores actual total and max(0,total-previousBaseline) delta. All other rank flags remain unchanged. Timestamp is UTC. Map replaces specified ranks; unmapped ranks remain. Grandfather makes no writes. A mapping between different ranks with equal order is counted as a promotion rather than falsely unchanged.

Preview200 data `{totalUsers,demoted,promoted,unchanged,changes:[{userId,username,currentRankName,newRankName,changeType,attendanceTotal}]}`. Full computed preview; no paging or hidden users. Other-user returned IDs audited once as `user_data.read`, resource `rank_migration`, with no snapshots. Self-only/empty preview no read audit; audit failure withholds result.

Apply200 data `{totalProcessed,demoted,promoted,unchanged}`. Entire visible plan commits atomically (Serializable,60second transaction limit), including every changed rank, rankHistory, bot outbox and audit. One failure rolls back earlier users; no partial-success/error strings. Each mutation audit `user_rank.migrated`, resource user_rank, target user ID, metadata with ISO timestamps and strategy; history triggeredBy system_migration with human actor ID or null bot actor. API audit retains bot token identity. Outbox user.rank_changed source migration; promotion/demotion derived from order. Realtime profile notifications follow commit and failures preserve successful response.

RankMigrationWizard uses apiRequest, canonical envelopes/errors, attendanceTotal, and removes partial-error logging. No endpoints deleted and no schema changes.

Tests:22 passing unit cases in tests/api/rank-migration.test.ts;5 real Prisma cases in tests/api-integration/rank-migration.test.ts. Real tests cover actual attendance semantics, hierarchy/private preview, bot actor/demotion, preserved flags, strict/missing references, and failure on the second audit proving earlier rank/history/outbox rollback. Integration coordinated centrally.
