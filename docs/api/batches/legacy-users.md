# Legacy user imports, mappings and application

Consolidates five old route files (`attendance/legacy-import/user-data`, its `/map`, `admin/import/legacy-user-data`, its `/map` and `/apply`) into three canonical resources. Both live user sessions and active bot tokens use shared authorization/envelopes; invalid explicit tokens never fall back. No query arguments on writes. All mutation transactions use Serializable isolation and a 30-second timeout; conflicts return409, missing references404, invalid payload422.

- `GET /attendance/legacy-users` requires attendance:view. Strict cursor/limit (50 default, capped100), search (username/legacy ID, max200), isMapped/isApplied booleans; ascending IDs with actual lookahead. DTO includes existing legacy scalar fields with dateJoined normalized to YYYY-MM-DD or null and importedAt UTC ISO, mappedUser limited to id/username. Historical unsupported date strings display null and are rejected if subsequently applied. No embedded user directory; clients use canonical /users. Returned other-user/unmapped identity reads are audited, excluding lookahead/self-only/empty pages.
- `POST /attendance/legacy-users/import` requires attendance:edit. Strict JSON `{csvData,previewOnly?:boolean,autoMap?:boolean}` replaces both CSV text and multipart variants; upload UI reads file text. Maximum1MB and1000rows. Quoted CSV and reordered exact seven headers supported. IDs must be unique in the CSV; existing legacy IDs are skipped, including duplicate-only successful retries. Counts must be nonnegative Int32; empty numeric cells preserve zero defaults. Date Joined accepts YYYY-MM-DD or DD/MM/YYYY input, validates real calendar dates and stores YYYY-MM-DD. Empty is null. Unknown rank abbreviations preserve import and an invalid-rank note, but cannot apply until the rank exists. autoMap requires superadmin; only exactly one case-insensitive username match maps, never an arbitrary first match. Returns `{imported,autoMapped,skipped,preview}`; preview lists candidates but creates no records. Auto-map preview reads are audited; writes audit created IDs/counts/target users without CSV/names.
- `PATCH /attendance/legacy-users` requires superadmin. Strict `{updates:[{id,mappedUserId:Int32|null}]}`,1–100 unique record IDs. Preflight every record/user before updating any; returns record DTOs in input order. Explicit null unmaps. Applied records cannot be remapped to a different user or unmapped; same-user refresh is allowed. One atomic `legacy_user.mapping_updated` audit per row includes old/new mapped user IDs and flags only.
- `POST /attendance/legacy-users/apply` requires superadmin. Strict `{ids:[positiveInt32]}`,1–100 unique IDs. Explicit bounded targets replace unbounded apply-all. Already applied IDs are skipped; otherwise every row must map to an existing user, have an unambiguous existing rank abbreviation and valid date/counts. Two pending records targeting one user, or a user with other applied legacy data, return409 to prevent multiple historical baselines. All references validate before writes.
- Apply upserts current rank/baseline/lastRankedUpAt at joined-date UTC midnight (or preserves existing date/defaultnow); existing retired/interviewDone flags survive. History retains import semantics, oldData historical total and TIG delta, now records the actual previous rank. Session history actors are user IDs; bots use null while audits identify the token. The `user.rank_changed` outbox event retains correction/legacy_import payload. UserRank, RankHistory, outbox, isApplied and `legacy_user.applied` audits commit together, including multi-row rollback. Result `{applied,skipped}`.
- Both UIs use canonical envelopes/pagination; admin file upload enables superadmin autoMap, manual mappings cap100, apply iterates selected pending IDs in chunks of100 and reports how many earlier batches committed if a later batch fails. Each chunk is atomic. Original permission boundaries are preserved: attendance editors cannot use autoMap or apply.

Validation:29 unit tests and six actual Prisma integration tests, including applied-data protection, real second-audit rollback, UTC dates, outbox/history state, credentials, preview and deduplication.
