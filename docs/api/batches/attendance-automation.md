# Attendance automation consolidation

Four canonical POST endpoints replace six overlapping session/bot routes. All require a live `attendance:edit` user grant or active bot token, with live target hierarchy checks. This closes unauthenticated write access on the old automation endpoints; public attendance reads are unchanged.

- `/attendance/events`: strict `{userId OR identity:{provider,providerUserId},isJoin,eventTime}`. Steam/Discord provider IDs are numeric17–20-digit strings. Explicit UTC timestamps normalize to ISOZ. Unlinked identities remain pending. Scoped consecutive duplicate-direction events return the existing event with `meta.duplicate`; earlier out-of-order events are retained. No provider identifiers are copied to audit or response.
- `/attendance/events/backfill`: `{cursor?,limit?}` processes ascending pending IDs, default100/max1000, with actual lookahead metadata. All matched targets authorize before any writes. Unmatched records remain pending; contradictory provider mappings fail409 rather than silently linking the wrong person. The shared login-time pending-event helper also drops empty OR branches, fixing accidental matches to unrelated pending events.
- `/attendance/sessions`: strict numeric userId, optional numeric orbatId, and checkinTime/checkoutTime. Explicit operation mode creates/uses attached attendance, including users without signups. Otherwise sessions remain unattached and recalculate signed-up main operations, including overnight windows. One open session per user/mode; checkout must follow its stored checkin. Session dates use UTC midnight. Sessions/audits/attendance/logs are atomic.
- `/orbats/{id}/attendance/compile`: `{}` compiles raw events for every signup. Preserves the previous raw compiler’s six-hour search buffer, clamped segments, start-only full-presence rule and deterministic no_show. All users authorize before writes. Repeated compile updates existing records; logs and audits record each run. Side operations reject compilation.

Session endpoints now share existing window-overlap and first/last-hour grace calculations. This intentionally fixes the old bot endpoint’s separate60-minute present/partial heuristic. Raw session duration remains ceil minutes; counted session presence uses existing attendance helpers. Multi-session overnight totals include earlier segments rather than only the current day. Closed-session retries are not receipt-based; raw event ingestion offers scoped duplicate suppression.

Serializable transactions include audit records and every related database effect. Audit snapshots contain IDs, timestamps, statuses and counts rather than provider identifiers or prose. Bots have no fabricated human log actor. No new bot outbox event type was introduced.

Tests:24 unit cases and7 real Prisma integration cases, covering session and token authentication, live hierarchy, unknown identities, duplicate scoping, pending mapping isolation, raw compiler math, attached and unattached overnight behavior, side-operation suppression, preflight failures and transaction rollback. OpenAPI fragment includes exact schemas and removed paths.
