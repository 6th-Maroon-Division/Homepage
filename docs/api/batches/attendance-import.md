# Direct operation attendance import

- `POST /orbats/{id}/attendance/import` replaces `/attendance/import`. Both live user sessions and active bot tokens require `attendance:edit`; every imported target must pass the same live permission hierarchy. Explicit invalid authorization never falls back to the session.
- Strict JSON `{records:[{username,date,status}]}`, 1–100 rows, one trimmed username per batch. `date` is a real UTC calendar date (`YYYY-MM-DD`); statuses are exactly `P`, `A`, `NA`, `LOA`, `NO`, `EO`. No query arguments. Invalid IDs/query/JSON return 400; invalid payload/date mismatch return 422.
- The operation must exist and be a main operation. Its UTC date is `startsAtUtc ?? eventDate`; undated/side operations return 409. Each row must match this date. `NO`/`EO` rows count as skipped; all other rows resolve an unambiguous username, require a signup on this exact operation, and reject existing attendance. Missing references return 404; ambiguous usernames/duplicates return 409.
- A Serializable transaction preflights every target before creating any attendance. `P` becomes present; `A`/`NA`/`LOA` become absent; legacy numeric duration fields remain zero. Attendance, import logs and one `attendance.imported` audit per row commit together. Audit data contains IDs and statuses only. Session actors retain their user ID; bot log actors are null and audit records identify the bot token. Existing import behavior does not produce a bot outbox event.
- Returns `200 {data:{imported,skipped,total},meta:{}}`. Failures return the common error envelope and roll back all rows. This removes partial-success responses and raw database error leakage. Concurrent write conflicts return 409 for retry after reloading.
- The CSV UI calls the canonical route, skips a literal header, validates row structure, uppercases legacy statuses and shows specific API failures. It explicitly labels UTC dates and the 100-row limit.

Validation: 21 unit tests and five real Prisma integration tests cover session/bot credentials, UTC dates, status conversion, cross-operation signup protection, hierarchy preflight, duplicate rejection, and rollback when a later audit write fails. Parent runs the integration suite centrally.
